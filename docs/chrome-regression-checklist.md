# Chrome 扩展回归清单

本文用于版本发布前的真实 Chrome 主流程验收。回归环境只能使用测试账号和脱敏订单，不得在截图、日志或问题记录中包含 appSecret、access token、真实地址、手机号或客户隐私数据。

## 一、环境准备

- [ ] 使用 `.nvmrc` 指定的 Node.js 版本，并确认 npm 主版本为 10。
- [ ] 执行 `npm ci`，确认可以从干净环境完整安装依赖。
- [ ] 执行 `npm run verify`，确认测试、TypeScript 校验和 Chrome 构建全部通过。
- [ ] 在 `chrome://extensions` 开启开发者模式，加载 `output/chrome-mv3`。
- [ ] 打开扩展 Service Worker 控制台，确认启动、存储迁移和定时任务注册没有异常。

## 二、店铺管理

- [ ] 新增测试店铺账号，确认名称、AppID 和 AppSecret 校验结果正确。
- [ ] 编辑账号名称或凭证后重新校验，确认旧 token 缓存不会继续使用。
- [ ] 导入多账号配置，确认预览、重复账号提示和最终账号数量正确。
- [ ] 切换活动账号，刷新 dashboard 后确认选择状态仍然正确。
- [ ] 删除测试账号，确认对应订单工作区、定时任务和 token 缓存被清理。

## 三、订单管理

- [ ] 首次进入“全部账号”，确认自动触发订单同步并显示同步进度。
- [ ] 切换单账号和全部账号，确认订单数量、账号名称和分页总数正确。
- [ ] 验证待发货默认筛选、售后筛选和近 7/30/90 天时间筛选。
- [ ] 分别使用本地搜索和服务器最新搜索查询订单号、商品标题和备注。
- [ ] 打开订单详情，确认商品图片、完整商品文本、状态和金额展示正确。
- [ ] 解密并复制真实地址，确认页面日志和 Service Worker 日志不包含隐私明文。
- [ ] 保存商品货源和内部采购关联，刷新 dashboard 后确认数据仍然存在。
- [ ] 读取淘宝采购订单，确认复用专用工作标签页且不会打断前一个任务。
- [ ] 遇到登录、滑块或验证码时，确认工作标签页会提示并允许人工恢复流程。
- [ ] 检查淘宝发货状态，确认快递公司和运单号可以回填微信小店发货。
- [ ] 开启自动发货后，仅对满足条件的订单自动提交，风险订单必须保持人工处理。
- [ ] 对符合条件的售后取消订单发起淘宝退款，确认自动选择原因并要求最终人工确认。

## 四、商品提审与违规检测

- [ ] 获取提审配额和草稿商品，确认账号隔离、分页和剩余配额正确。
- [ ] 手动执行一次商品提审任务，确认黑名单错误码、跳过关键词和状态规则生效。
- [ ] 创建账号级和全账号提审任务，确认排除账号、错峰和每日限制正确。
- [ ] 导入违规词文件，分别验证批量扫描、逐条处理、跳过、删除和停止操作。
- [ ] 确认高频诊断信息只出现在 Service Worker 控制台，不进入页面日志中心。

## 五、调度、日志与通知

- [ ] 确认订单增量同步、历史补拉和发货检查系统任务自动存在。
- [ ] 使用“立即执行”验证任务成功、跳过和失败三种结果展示。
- [ ] 禁用、启用和删除用户任务，确认 Chrome alarm 与页面状态同步。
- [ ] 检查日志中心的开始、完成、失败、等待用户和错误详情展示。
- [ ] 验证通知偏好开关，只允许带明确 notification topic 的 ActivityLog 生成通知。
- [ ] 清空日志和通知后刷新页面，确认持久化状态正确。

## 六、发布验收

- [ ] 检查 `output/chrome-mv3/manifest.json` 的版本、权限和 host permissions。
- [ ] 确认 dashboard、background 和淘宝 content script 均来自本次构建。
- [ ] 关闭并重新打开 Chrome 后重复一次订单同步和淘宝工作标签页流程。
- [ ] 执行 `npm run zip`，确认压缩包可以重新加载且不包含 source map、凭证或客户数据。
- [ ] 在发布说明中记录验证命令、权限变化、已知限制和对应截图或录屏。
